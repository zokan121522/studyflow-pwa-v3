# studyflow-pwa-v3

> studyflow-hub v3 como Progressive Web App (PWA)
> Repo separado para SDD completo. Integración posterior en studyflow-hub.

## Stack
- **Backend**: Python 3.12 + Flask 3.1.1 + gunicorn (API)
- **Frontend**: PWA — SPA vanilla JS/CSS modular + Service Worker + Web App Manifest + cache offline
- **Database**: PostgreSQL 16 (psycopg2-binary)
- **Contenedores**: Docker Compose (Flask + PostgreSQL)
- **AI**: Ollama (qwen2.5:7b, llama3.2-3b) + edge-tts
- **PDF**: PyMuPDF, pdfplumber, weasyprint

## Release ritual (multi-platform)

The project ships **three portable zips**, one per OS, each with its own launcher and a build-generated `LEEME-PRIMERO.txt`:

| OS | Zip | Launcher |
|----|-----|----------|
| Windows | `dist/StudyFlow-windows-<ver>.zip` | `INICIAR_StudyFlow.bat` → `launcher/StudyFlow.bat` |
| macOS | `dist/StudyFlow-macos-<ver>.zip` | `launcher/StudyFlow.command` |
| Linux | `dist/StudyFlow-linux-<ver>.zip` | `bash launcher/StudyFlow.sh` |

### 1) 3-OS quality gate (before production)

A commit to `main` triggers the autodeploy, so **before** any feature reaches `main`, Álvaro tests the dev zips on the three real devices:

- **Mac** — this machine.
- **Windows** — the Asus, remote-controlled from the Mac via TeamViewer.
- **Linux** — virtual machine.

Per-OS checklist:
1. Unzip the dev zip.
2. Run the launcher (double-click `INICIAR_StudyFlow.bat` / `StudyFlow.command`, or `bash launcher/StudyFlow.sh`).
3. First run installs dependencies (2–3 min).
4. Server starts and the browser opens at `http://127.0.0.1:8477/`.
5. The in-app version pill shows the expected version.
6. Close the window / Ctrl+C stops the server.

Only if **all three pass** → version bump + conventional commit + push to `main`.

### 2) Build the three zips

```bash
bash scripts/build-windows-portable.sh && \
bash scripts/build-macos-portable.sh   && \
bash scripts/build-linux-portable.sh
# → dist/StudyFlow-<so>-<version>.zip
```

### 3) Technical notes

- `.bat` files MUST keep CRLF: declared `-text` in `.gitattributes` (after `* text=auto`, so git never renormalises them).
- `.bat` text must be pure ASCII (OEM codepage) — no accented/UTF-8 bytes.
- `LEEME-PRIMERO.txt` per platform is generated by its build script during the build; never hand-edit it.

### 4) Publishing & quick links

`deploy/downloads/publish.sh` publishes the zips and writes `version.json` (`platforms`) for the downloads page. `scripts/autodeploy.sh` (LaunchAgent `com.studyflow.autodeploy`, every 180 s, SHA gate on `main`) builds and publishes all three.

[build-windows](scripts/build-windows-portable.sh) · [build-macos](scripts/build-macos-portable.sh) · [build-linux](scripts/build-linux-portable.sh) · [publish](deploy/downloads/publish.sh) · [autodeploy](scripts/autodeploy.sh)

## Canal BETA (obligatorio)

```
FLUJO StudyFlow  (feature o fix)   --  canal BETA obligatorio

 1 CONSENSO       Senor + Alvaro: que, por que, criterio de aceptacion
 2 RAMA           feat/<fase>-<desc>  (worktree + SDD engram)
 3 IMPLEMENTAR    hijos: coder (escribe) | test (ejecuta) | review (diff)
 4 VERIFICAR      pytest full + verify-frontend + verificacion INDEPENDIENTE
 5 BUILD          3 zips (macos / windows / linux) -> dist/
 6 BETA           version.json: stable INTACTO + bloque "beta"
                  zips *-beta.zip  (-latest SIN tocar)  pagina: badge BETA
                  + audio/texto de novedades
 7 PRUEBA REAL    Senor: descarga DESDE LA PAGINA OFICIAL
                  + uso como usuario en Mac / Windows / Linux   (= gate 3-SO)
 8 VISTO BUENO?   no -> feedback -> volver a 3 (sigue beta, mismo numero)
                  si -> 9
 9 PROMOCION      version.json stable = 3.1.x   -latest -> 3.1.x
                  quitar badge BETA   congelar sha
10 COMMIT/PUSH    conventional commit + push a main -> autodeploy (SHA gate)
11 ARCHIVO        Engram + Obsidian (retro)
```

- (a) ninguna versión pasa a oficial sin que el Señor la descargue de la página oficial y la pruebe como usuario;
- (b) mientras sea beta, el canal estable y los `-latest` NO se tocan;
- (c) si el binario cambia durante la beta, rehacer zips + sha y volver a avisar (mismo número mientras siga en beta);
- (d) el gate 3-SO ES la prueba real de la beta, no un paso extra.
